# 입력 전문 검증

`MTDataMaker`와 `MXDataMaker`가 파일에서 읽은 내용을 전송 전에 검증합니다. 실패하면 전송하지 않고 기존 오류 처리 경로를 통해 해당 파트너의 `error_path/failed-*/`에 원본을 보관합니다. 상세 오류는 로그에 기록됩니다.

## 데이터 경로

현재 작업 폴더를 기준으로 다음 파일을 사용합니다. 애플리케이션은 시작할 때 실행 파일이 있는 폴더로 작업 폴더를 변경합니다.

| 경로 | 필수 CSV 열 / 용도 |
| --- | --- |
| `data/ref/bic.csv` | `BIC8`, `BIC11` |
| `data/ref/currency.csv` | `Code` |
| `data/ref/country.csv` | `Code` |
| `data/sr/*.xsd` | MX AppHdr 및 Document 스키마 |

CSV가 없거나 필요한 열/코드가 비어 있으면 입력을 거부합니다. UTF-8 BOM, 인용부호 및 열/코드 앞뒤 공백을 처리합니다. 참조 목록과 컴파일한 XSD를 메모리에 보관하므로 데이터를 교체한 뒤에는 애플리케이션을 재시작합니다. MT는 XSD 파일을 사용하지 않습니다.

## BIC

BIC를 CSV와 대조할 때 8번째 문자만 `0`으로 바뀐 형태도 허용합니다. 예를 들어 CSV의 `BANKKRSE`에 대해 `BANKKRS0`을 허용하며, `BANKKRSEXXX`에 대해 `BANKKRS0XXX`을 허용합니다. 앞 7자리와 11자리 BIC의 지점 코드는 등록된 값과 일치해야 합니다. 이 규칙은 MT와 MX에 공통 적용되며 전송할 원문의 BIC를 변경하지 않습니다.

## MX

- `AppHdr`, `Document`의 ISO 20022 네임스페이스에 대응하는 XSD를 선택합니다.
- `AppHdr/BizSvc`가 있으면 `<전문종류>-<BizSvc>.xsd`를 사용합니다. 일치하는 파일이 없으면 오류로 처리합니다.
- 같은 이름의 `_BAH.xsd`가 있으면 헤더에도 해당 서비스의 제약을 적용합니다. 없으면 헤더 네임스페이스의 XSD를 사용합니다.
- `Ccy` 속성, 통화·국가·BIC 요소 및 XSD가 해당 코드형으로 식별한 요소를 CSV와 대조합니다. BIC는 8자리/11자리를 구분하며 BIC에 포함된 국가 코드도 확인합니다.
- 입력에는 하나의 `Body`와 그 직계 자식인 `AppHdr`, `Document`가 각각 하나씩 있어야 합니다. 본문 추출 시 상위 요소의 네임스페이스 선언을 보존합니다.
- 오류에 요소 경로와 XML 행·열을 포함합니다.

## MT

FIN 헤더의 송수신 LT 주소는 논리 터미널 문자를 제외한 BIC11로 변환하여 대조합니다. 본문의 명시적인 코드 필드를 검사하며, 자유 형식 이름·주소·송금 설명에서 코드를 추측하지 않습니다.

| 검사 | 대상 필드 |
| --- | --- |
| BIC | `50A`~`59A`의 정의된 A 옵션, `82A`~`89A`, MT101 `50C`, `95P`, `94F` |
| 통화 | `32A/B`, `33A/B`, `34A/B/F`, `60F/M`, `62F/M`, `64`, `65`, `71F/G`, `11A`, `19A/B`, `90B/F`, `92B/F/H/M` |
| 국가 | `50F`, `59F`의 국가 하위 필드, `77B`의 `/ORDERRES/`·`/BENEFRES/`, `94C`, BIC에 포함된 국가 코드 |

오류에 MT 필드 및 블록 4 내 행 위치를 포함합니다. 이 검사는 위 필드의 참조 코드 검증이며, 모든 MT 전문의 필수 필드·업무 규칙이나 자유 형식 주소의 국가를 검증하는 기능은 아닙니다.
